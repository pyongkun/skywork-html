이 책을 읽는 법

이 교재는 다음 세 층을 분리해서 설명한다.

  1. Ghostty 기능: 글자를 화면에 그리는 macOS 터미널 앱, 탭·분할·폰트·테마·키 바인딩·셸 통합·ghostty +ssh 등
  2. SSH·shell 기능: 원격 접속, 인증, 명령 해석, 환경 변수, 파이프, 리다이렉션, 파일 전송 등
  3. Linux 서버 기능: 파일·권한·프로세스·로그·디스크·GPU·Python 환경·tmux·Jupyter·Git 등

Ghostty가 딥러닝을 실행하는 것은 아니다. Ghostty 안의 shell이 ssh를 실행하고, SSH로 연결된 Linux 서버가 Python과 GPU 학습을 실행한다. 이 경계를 이해하면 장애가 어느 층에서 생겼는지 판단하기 쉬워진다.

<HOST>        서버 주소               예: gpu.example.edu
<PORT>        SSH 포트                예: 22 또는 관리자가 준 값
<ALIAS>       SSH config 별칭          예: gpu-lab
<PROJECT>     프로젝트명              예: vision-exp
<REMOTE_DIR>  서버 프로젝트 경로      예: /home/alice/projects/vision-exp

2. Ghostty 설치와 첫 실행

Ghostty는 macOS 네이티브 UI와 GPU 가속 렌더링을 사용하는 터미널 에뮬레이터다. 공식 macOS 바이너리는 .dmg로 제공되며, 설정 없이도 실행할 수 있다.12

2.1 공식 DMG 설치

  1. 공식 다운로드 페이지에서 macOS .dmg를 받는다.
  2. 파일을 열고 Ghostty를 Applications로 드래그한다.
  3. Applications에서 Ghostty를 실행한다.
  4. macOS가 출처 확인을 요구하면 시스템 설정의 개인정보 보호 및 보안에서 확인한다. 보안 경고를 무조건 우회하지 말고 다운로드 출처를 다시 확인한다.

2.2 Homebrew 설치

brew install --cask ghostty

Homebrew가 없다면 먼저 공식 설치법을 검토한다. 인터넷에서 출처 불명의 curl ... | sh 명령을 그대로 실행하지 않는다.

2.3 설치 확인과 버전 의존성 확인

command -v ghostty
ghostty --version
ghostty +help 2>/dev/null || ghostty --help

GUI 앱으로 설치하면 shell의 PATH에서 ghostty 명령을 바로 찾지 못할 수 있다. 이때 앱 자체가 고장 난 것은 아니다. Ghostty 메뉴·공식 문서에서 CLI 설치 방식을 확인하거나 다음처럼 앱 번들 내 실행 파일 존재 여부를 조회만 한다.

ls -l /Applications/Ghostty.app/Contents/MacOS/

버전 주의: ghostty +ssh는 공식 조사 자료상 1.3.x에는 없고 1.4.0이 될 개발 버전에 추가된 기능으로 설명되어 있다. 반면 SSH 관련 shell integration 기능은 1.3.x에 존재한다.3 따라서 이 책의 +ssh 예제를 실행하기 전 반드시 ghostty +ssh --help로 현재 설치본의 지원 여부를 확인한다.

3. 터미널과 shell의 기초

3.1 터미널과 shell은 다르다

  • Ghostty: 키 입력을 shell에 전달하고 결과를 화면에 렌더링한다.
  • shell: cd, 변수 확장, 파이프, 리다이렉션을 해석한다. macOS 기본 대화형 shell은 흔히 zsh다.
  • 명령/프로그램: ssh, python, git, ls처럼 shell이 실행하는 프로그램이다.
# 현재 shell로 등록된 경로
printf '%s\n' "$SHELL"

# 현재 프로세스 계층 일부
ps -p $$ -o pid,ppid,command=

# 명령의 정체 확인: builtin, alias, function, executable 등
type cd
type ssh
type python

3.2 경로와 이동

pwd                     # 현재 위치
ls                      # 현재 디렉터리 목록
ls -la                  # 숨김 파일과 상세 정보
cd /absolute/path       # 절대 경로
cd relative/path        # 상대 경로
cd ..                   # 상위 디렉터리
cd ~                    # 홈
cd -                    # 직전 디렉터리

공백이 있는 경로는 반드시 인용한다.

cd "$HOME/My Projects"

3.3 명령 구조와 도움말

명령 [옵션] [인자]
ls   -lah   ~/projects

man ssh
ssh -h
ssh -V
python --help

man에서는 /검색어, n(다음), N(이전), q(종료)를 익힌다.

3.4 파이프와 리다이렉션

nvidia-smi | less                 # 출력을 페이지 단위로 보기
python train.py >train.log 2>&1   # stdout과 stderr를 파일에 기록
python train.py 2>&1 | tee train.log  # 화면과 파일에 동시에 기록
  • >: 파일을 새로 덮어쓴다.
  • >>: 끝에 추가한다.
  • 2>: 오류 출력만 보낸다.
  • |: 왼쪽 명령의 stdout을 오른쪽 명령의 stdin으로 보낸다.

경고: >는 기존 파일을 조용히 덮어쓸 수 있다. 중요한 로그에는 >> 또는 새 타임스탬프 파일을 사용한다.

log_file="logs/train_$(date +%Y%m%d_%H%M%S).log"
mkdir -p logs
python train.py 2>&1 | tee "$log_file"

3.5 따옴표와 변수

name='world'
printf 'literal: $name\n'       # 작은따옴표: 확장 안 함
printf "expanded: %s\n" "$name" # 큰따옴표: 변수 확장

변수는 기본적으로 큰따옴표로 감싼다: "$file". 그렇지 않으면 공백·와일드카드 때문에 예상치 못한 여러 인자로 나뉠 수 있다.

4. Ghostty 기본 조작과 설정

Ghostty는 창·탭·분할을 네이티브 UI 구성 요소로 제공하고, macOS에서는 Metal로 화면을 렌더링한다.4

4.1 먼저 메뉴에서 현재 단축키 확인

버전, macOS 키보드 배열, 사용자 설정에 따라 단축키가 다를 수 있다. 메뉴 막대의 File, Edit, View, Window 항목에 표시되는 키를 기준으로 한다. 조사 자료에서 대표 기본값은 다음과 같다.

  • 새 탭: Cmd+T
  • 분할: Cmd+D, Cmd+Shift+D
  • 복사/붙여넣기: 일반적인 macOS 방식인 Cmd+C, Cmd+V

하지만 터미널에서 Ctrl+C는 복사가 아니라 실행 중 프로세스에 인터럽트 신호를 보내는 키다.

4.2 선택과 프롬프트 이동

Ghostty shell integration은 프롬프트 재그리기, 이전 작업 디렉터리에서 새 터미널 시작, 프롬프트 단위 이동 같은 기능을 제공한다. macOS에서 Command를 누른 채 세 번 클릭하면 한 명령의 출력을 선택할 수 있고, Option+click은 프롬프트에서 커서를 클릭 위치로 이동시키는 기능을 제공한다.5

4.3 설정 파일 위치

Ghostty 설정은 텍스트 파일이다. 현재 공식 문서 기준으로 파일명은 config.ghostty이며, 1.2.3 이전에는 config도 사용했다. macOS에서는 XDG 경로와 Application Support 경로를 지원한다.6

권장 경로:

~/.config/ghostty/config.ghostty

다른 macOS 경로:

~/Library/Application Support/com.mitchellh.ghostty/config.ghostty

생성:

mkdir -p "$HOME/.config/ghostty"
${EDITOR:-nano} "$HOME/.config/ghostty/config.ghostty"

4.4 옵션을 추측하지 않는 법

Ghostty 옵션은 버전에 따라 추가·변경될 수 있다.

  1. ghostty --version 기록
  2. 공식 Option Reference 검색
  3. 가능하면 CLI 도움말 또는 설정 검사 기능 확인
  4. 한 번에 한 옵션만 추가
  5. 재로딩 후 로그·화면 확인
  6. 문제가 나면 방금 추가한 줄을 주석 처리

폰트 목록은 다음 명령으로 확인한다.7

ghostty +list-fonts

4.5 보수적인 추천 설정 템플릿

아래는 출발점이다. 폰트명과 테마명은 설치본에서 확인한다. 키 바인딩은 기본값을 먼저 익힌 뒤 추가한다.

# ~/.config/ghostty/config.ghostty

# ghostty +list-fonts로 실제 이름을 확인한 뒤 설정
font-family = "<INSTALLED_MONOSPACE_FONT>"
font-size = 13

# 공식 레퍼런스와 현재 설치본에서 이름을 확인
# theme = <THEME_NAME>

# 대화형 ssh를 Ghostty가 보조하도록 하는 기능.
# 현재 버전에서 지원되는지 공식 문서와 로그를 확인한다.
shell-integration-features = ssh-env,ssh-terminfo

주의: 조사 요약의 theme = dark는 문법 예시이지 모든 버전에서 원하는 테마를 보장하는 추천값이 아니다. 실제 테마명·옵션은 현재 Option Reference에서 확인한다.

4.6 Ghostty shell integration

Ghostty는 zsh, bash, fish, elvish, nushell 등의 통합을 자동 주입할 수 있다. 다만 macOS 기본 /bin/bash는 자동 통합 대상에서 제한이 있으므로 수동 source 또는 최신 Bash 설치가 필요할 수 있다.5

자동 통합을 끄는 예:

shell-integration = none

shell을 바꿔 실행하거나 nix-shell 등으로 새 shell에 들어가면 처음 주입된 통합이 이어지지 않을 수 있다. 수동 통합 경로와 현재 GHOSTTY_RESOURCES_DIR을 점검한다.

printf '%s\n' "${GHOSTTY_RESOURCES_DIR:-not-set}"

5. SSH를 안전하게 시작하기

5.1 접속 전 받아야 할 정보

관리자에게 다음을 확인한다.

  • <HOST>: DNS 이름 또는 IP
  • <PORT>: 기본 22인지 별도 포트인지
  • <USER>: 계정명
  • VPN 또는 기관망 필요 여부
  • 공개키 등록 절차
  • bastion/jump host 필요 여부
  • GPU 사용 정책, 스케줄러(Slurm 등) 여부
  • 허용된 저장 위치와 quota

5.2 첫 접속

ssh -p <PORT> <USER>@<HOST>

처음 보이는 host key fingerprint는 서버 신원을 확인하는 장치다. 그냥 yes를 누르지 말고 관리자가 별도 채널로 제공한 fingerprint와 비교한다.

접속 직후:

whoami
hostname
pwd
printf '%s\n' "$HOME" "$SHELL" "$TERM"

종료:

exit

또는 shell 입력이 정상일 때 Ctrl+D를 사용할 수 있다.

5.3 SSH 키 생성

Mac에서 서버별 키를 별도 파일로 만들면 폐기와 회수가 쉽다.

ssh-keygen -t ed25519 -a 100 -f "$HOME/.ssh/id_ed25519_gpu_lab" -C "<USER>@<MAC_NAME>-gpu-lab"
  • 강한 passphrase를 설정한다.
  • 개인키 <KEY_PATH>는 공유하지 않는다.
  • .pub 공개키만 관리자나 등록 시스템에 제공한다.

권한 확인:

chmod 700 "$HOME/.ssh"
chmod 600 "$HOME/.ssh/id_ed25519_gpu_lab"
chmod 644 "$HOME/.ssh/id_ed25519_gpu_lab.pub"

위험: 개인키 내용을 메신저·이메일·Git 저장소에 붙여 넣지 않는다. cat ~/.ssh/id_ed25519_gpu_lab도 화면 공유 중에는 하지 않는다.

5.4 공개키 등록

관리자가 ssh-copy-id를 허용한 경우:

ssh-copy-id -i "$HOME/.ssh/id_ed25519_gpu_lab.pub" -p <PORT> <USER>@<HOST>

macOS에 ssh-copy-id가 없다면 공개키 한 줄을 관리자의 공식 등록 포털로 제출하거나, 관리자가 안내한 방식만 따른다. 암호로 접속 가능한 서버라면 다음 방식도 가능하지만, 원격 명령 인용을 이해한 뒤 사용한다.

cat "$HOME/.ssh/id_ed25519_gpu_lab.pub" | \
  ssh -p <PORT> <USER>@<HOST> \
  'umask 077; mkdir -p ~/.ssh; cat >> ~/.ssh/authorized_keys'

5.5 macOS Keychain과 agent

ssh-add --apple-use-keychain "$HOME/.ssh/id_ed25519_gpu_lab"
ssh-add -l

OpenSSH 빌드에 따라 --apple-use-keychain 지원이 다를 수 있으므로 실패하면 ssh-add --help 또는 man ssh-add를 확인한다. agent forwarding은 기본적으로 켜지 않는다.

5.6 ~/.ssh/config 작성

# ~/.ssh/config
Host gpu-lab
    HostName <HOST>
    User <USER>
    Port <PORT>
    IdentityFile ~/.ssh/id_ed25519_gpu_lab
    IdentitiesOnly yes
    ServerAliveInterval 60
    ServerAliveCountMax 3
    AddKeysToAgent yes
    UseKeychain yes

chmod 600 "$HOME/.ssh/config"
ssh gpu-lab

UseKeychain은 macOS OpenSSH 관련 옵션이므로 다른 OS에서 같은 config를 공유하면 호환성을 점검한다. 실제 적용값은 다음으로 확인한다.

ssh -G gpu-lab | less

5.7 jump host

Host bastion
    HostName <BASTION_HOST>
    User <BASTION_USER>
    Port <BASTION_PORT>
    IdentityFile ~/.ssh/id_ed25519_bastion

Host gpu-private
    HostName <PRIVATE_GPU_HOST>
    User <USER>
    Port <PORT>
    IdentityFile ~/.ssh/id_ed25519_gpu_lab
    ProxyJump bastion

6. Ghostty와 SSH의 접점: terminfo

원격 프로그램은 $TERM과 terminfo를 이용해 색상·키·화면 제어 능력을 판단한다. Ghostty는 xterm-ghostty를 사용할 수 있지만 원격 서버에 해당 terminfo가 없으면 Error opening terminal: xterm-ghostty 같은 오류가 날 수 있다.8

6.1 ghostty +ssh 지원 버전

지원 여부부터 확인한다.

ghostty +ssh --help

지원한다면:

ghostty +ssh -- <USER>@<HOST>
ghostty +ssh -- -p <PORT> <USER>@<HOST>
ghostty +ssh -- gpu-lab

공식 문서에 따르면 +ssh는 실제 ssh 인자를 전달하면서 원격 terminfo 설치와 일부 환경 전달을 준비한다. terminfo 설치가 실패하면 경고 후 TERM=xterm-256color로 fallback할 수 있다.3

6.2 자동 wrapper

shell-integration-features = ssh-env,ssh-terminfo

이 설정은 대화형 shell에서 ssh 함수를 감싸 +ssh 동작을 사용하도록 할 수 있다. 그러나 shell function은 rsync, scp, sftp, Git, gcloud, cron, 스크립트 같은 자식 프로세스가 직접 호출하는 ssh에는 적용되지 않는다.3

확인:

type ssh
command -V ssh

원래 실행 파일을 명시해야 할 때:

command ssh gpu-lab
/usr/bin/ssh gpu-lab

6.3 안전한 fallback

Ghostty 전용 terminfo가 없고 설치 권한도 없다면 해당 호스트에 한해 xterm-256color를 사용하도록 SSH 설정을 검토할 수 있다.

Host legacy-gpu
    HostName <HOST>
    User <USER>
    SetEnv TERM=xterm-256color

SetEnv는 OpenSSH 버전에 따라 지원 여부가 다르며, 원격에 xterm-ghostty가 이미 있으면 기능을 불필요하게 낮출 수 있다.3 먼저 다음을 확인한다.

ssh -V
ssh legacy-gpu 'infocmp xterm-ghostty >/dev/null 2>&1; echo $?'

7.3 rsync

반복 전송·중단 재개에는 rsync가 유용하다.

# 먼저 변경 예정만 확인
rsync -avhn --progress \
  --exclude '.git/' --exclude '__pycache__/' --exclude '*.pt' \
  "<LOCAL_DIR>/" "gpu-lab:<REMOTE_DIR>/"

# 확인 후 실제 실행: -n만 제거
rsync -avh --progress --partial \
  --exclude '.git/' --exclude '__pycache__/' --exclude '*.pt' \
  "<LOCAL_DIR>/" "gpu-lab:<REMOTE_DIR>/"

매우 위험: --delete는 목적지의 불필요한 파일을 삭제한다. 첫 실행에는 사용하지 말고 반드시 -n/--dry-run 결과를 검토한다. 체크포인트와 데이터셋 디렉터리를 별도 백업 없이 동기화 삭제하지 않는다.

비표준 포트 또는 config를 쓰지 않을 때:

rsync -avhn -e 'ssh -p <PORT>' "<LOCAL_DIR>/" "<USER>@<HOST>:<REMOTE_DIR>/"

8. SSH 포트 포워딩과 Jupyter

8.1 로컬 포워딩 개념

Mac localhost:<LOCAL_PORT>
  → 암호화된 SSH 연결
  → 서버에서 본 localhost:<REMOTE_PORT>

ssh -N -L <LOCAL_PORT>:127.0.0.1:<REMOTE_PORT> gpu-lab
  • -L: local forwarding
  • -N: 원격 shell 명령을 실행하지 않고 터널만 유지
  • 포트가 이미 사용 중이면 다른 <LOCAL_PORT>를 고른다.

8.2 Jupyter 안전 실행

서버에서:

cd <REMOTE_DIR>
source .venv/bin/activate
jupyter lab --no-browser --ip=127.0.0.1 --port=<JUPYTER_PORT>

Mac의 새 Ghostty 탭에서:

ssh -N -L <LOCAL_PORT>:127.0.0.1:<JUPYTER_PORT> gpu-lab

브라우저:

http://127.0.0.1:<LOCAL_PORT>/

보안 경고: Jupyter를 무심코 --ip=0.0.0.0로 외부에 노출하지 않는다. 127.0.0.1에 바인딩하고 SSH 터널로 접근한다. 토큰을 채팅이나 저장소에 올리지 않는다.

8.3 포워딩을 config로 정의

Host gpu-jupyter
    HostName <HOST>
    User <USER>
    Port <PORT>
    IdentityFile ~/.ssh/id_ed25519_gpu_lab
    LocalForward <LOCAL_PORT> 127.0.0.1:<JUPYTER_PORT>
    ExitOnForwardFailure yes

ssh -N gpu-jupyter

8.4 원격·동적 포워딩 주의

  • -R은 원격 측 포트를 연다. 조직 정책과 GatewayPorts 설정을 이해하지 못하면 사용하지 않는다.
  • -D는 SOCKS 프록시를 만든다. 트래픽 정책을 우회하는 용도로 사용하지 않는다.

위험 명령: rm은 휴지통을 거치지 않는다.

안전한 순서:

# 1) 대상 조회
printf 'target=%q\n' "<TARGET>"
ls -ld -- "<TARGET>"

# 2) 파일 하나를 대화형 삭제
rm -i -- "<TARGET_FILE>"

# 3) 디렉터리는 먼저 비었는지 확인
find "<TARGET_DIR>" -maxdepth 2 -print

rm -rf는 프로젝트 루트, 변수, glob과 결합할 때 특히 위험하다. 빈 변수 방어 없이 rm -rf "$DIR"/* 같은 코드를 작성하지 않는다. 가능하면 버전 관리·백업·격리 디렉터리를 사용한다.

10. 권한과 소유권

ls -l file
stat file
id
groups
umask

권한은 소유자(user), 그룹(group), 기타(other)의 읽기(r), 쓰기(w), 실행(x)으로 구성된다.

chmod u+x script.sh
chmod 600 secret.env
chmod 700 ~/.ssh
chmod 644 ~/.ssh/authorized_keys
  • 디렉터리의 x는 진입·탐색 권한과 관련된다.
  • chmod 777은 문제를 숨기는 위험한 임시방편이다.
  • chown은 보통 root 권한이 필요하다.

경고: sudo chmod -R 777 <DIR> 또는 sudo chown -R을 원인 파악 없이 실행하지 않는다. 공유 GPU 서버에서는 다른 사용자 데이터와 서비스까지 손상할 수 있다. 먼저 namei -l <PATH>, ls -ld, id, ACL 여부(getfacl이 있다면)를 확인하고 관리자에게 문의한다.

sudo 사용 전 체크:

whoami
pwd
printf '%q\n' "<TARGET_PATH>"

서버에 sudo 권한이 없다는 것은 정상일 수 있다. Python 패키지를 설치하려고 sudo pip install을 사용하지 말고 가상환경을 사용한다.

12. tmux: 연결이 끊겨도 작업 유지하기

Ghostty 탭·분할은 Mac 앱의 UI다. tmux 세션은 서버 프로세스다. Mac이 절전되거나 SSH가 끊겨도 서버와 tmux가 살아 있으면 작업을 다시 붙일 수 있다.

12.1 기본 사용

tmux new -s <PROJECT>

기본 prefix는 Ctrl+b다. Ctrl+b를 누르고 손을 뗀 뒤 다음 키를 누른다.

c       새 window
n/p     다음/이전 window
%       좌우 pane 분할
"       상하 pane 분할
방향키  pane 이동
[       copy mode
?       키 목록

분리(detach): Ctrl+b, 이어서 d

tmux ls
tmux attach -t <PROJECT>
tmux new -A -s <PROJECT>  # 있으면 붙고 없으면 생성

세션 종료:

tmux kill-session -t <PROJECT>

학습 프로세스가 실행 중인 pane에서 exit하거나 세션을 kill하면 작업도 종료될 수 있다. 먼저 체크포인트 저장 여부와 프로세스를 확인한다.

12.2 tmux 실전 배치

  • window 1: 학습 명령
  • window 2: watch -n 2 nvidia-smi
  • window 3: tail -F logs/train.log
  • window 4: Git·편집·검증

12.3 tmux가 없는 서버

관리자에게 설치를 요청하거나 스케줄러를 사용한다. nohup은 단순 대안이지만 상호작용·로그 관리가 불편하다.

nohup python -u train.py >logs/train.log 2>&1 &
printf '%s\n' "$!" >run.pid

종료 전:

pid="$(cat run.pid)"
ps -p "$pid" -o pid,etime,command=
kill -TERM "$pid"

14. CUDA와 GPU 모니터링

14.1 층을 구분한다

GPU 하드웨어
→ NVIDIA driver(호스트)
→ CUDA runtime/toolkit
→ Python 패키지(PyTorch 등)
→ 사용자 코드

nvidia-smi에 보이는 CUDA 표기와 로컬 nvcc 버전, PyTorch가 빌드된 CUDA 버전은 서로 같은 의미가 아닐 수 있다. 숫자 하나만 보고 호환된다고 단정하지 않는다.

14.2 기본 점검

nvidia-smi
nvidia-smi -L
watch -n 2 nvidia-smi

Python/PyTorch:

python - <<'PY'
import torch
print('torch:', torch.__version__)
print('built CUDA:', torch.version.cuda)
print('available:', torch.cuda.is_available())
print('device count:', torch.cuda.device_count())
if torch.cuda.is_available():
    print('device 0:', torch.cuda.get_device_name(0))
PY

TensorFlow를 쓴다면 해당 프레임워크 공식 점검 API를 사용한다.

14.3 특정 GPU 선택

관리자나 스케줄러가 할당한 GPU만 사용한다.

CUDA_VISIBLE_DEVICES=<GPU_INDEX> python train.py

CUDA_VISIBLE_DEVICES=1로 실행하면 프로그램 내부에서는 그 GPU가 cuda:0으로 보일 수 있다. Slurm 환경에서는 임의 지정 대신 할당 환경 변수를 따른다.

14.4 메모리 부족(OOM)

  1. 다른 프로세스와 점유량 확인
  2. 자신의 유령 프로세스 확인
  3. batch size 감소
  4. gradient accumulation 검토
  5. mixed precision 검토
  6. 입력 크기·모델 크기·캐시 점검
  7. checkpoint로 재시작 가능하게 설계

다른 사용자의 GPU 프로세스를 종료하지 않는다. PID와 사용자명을 확인하고, 정책 위반이나 고아 프로세스는 관리자에게 문의한다.

데이터셋, 모델 가중치, API 키, SSH 키를 일반 Git에 commit하지 않는다. 큰 모델은 조직이 허용하는 artifact storage 또는 Git LFS 정책을 따른다.

16.4 비밀이 commit된 경우

파일을 삭제한 commit만으로 과거 기록에서 비밀이 사라지지 않는다.

  1. 키·토큰 즉시 폐기/회전
  2. 저장소 관리자에게 알림
  3. 허가된 절차로 기록 정리
  4. 협업자에게 영향 공지

git reset --hard, git clean -fdx는 작업을 잃게 할 수 있다. 실행 전 git status, 백업 branch, dry-run(git clean -ndx)을 사용한다.

17. 안전한 셸 스크립트

다음은 학습 명령을 기록 가능하게 실행하는 Bash 예제다.

#!/usr/bin/env bash
set -euo pipefail
IFS=$'\n\t'

usage() {
  cat <<'EOF'
Usage: run_train.sh --config PATH [--name NAME]
EOF
}

config=''
name='experiment'

while (($# > 0)); do
  case "$1" in
    --config)
      [[ $# -ge 2 ]] || { printf 'ERROR: --config needs a value\n' >&2; exit 2; }
      config=$2
      shift 2
      ;;
    --name)
      [[ $# -ge 2 ]] || { printf 'ERROR: --name needs a value\n' >&2; exit 2; }
      name=$2
      shift 2
      ;;
    -h|--help)
      usage
      exit 0
      ;;
    *)
      printf 'ERROR: unknown argument: %s\n' "$1" >&2
      usage >&2
      exit 2
      ;;
  esac
done

[[ -n "$config" ]] || { printf 'ERROR: --config is required\n' >&2; exit 2; }
[[ -f "$config" ]] || { printf 'ERROR: config not found: %s\n' "$config" >&2; exit 1; }
command -v python >/dev/null || { printf 'ERROR: python not found\n' >&2; exit 1; }

mkdir -p logs checkpoints
stamp=$(date +%Y%m%d_%H%M%S)
log_file="logs/${name}_${stamp}.log"

printf 'host=%s\nconfig=%s\nlog=%s\n' "$(hostname)" "$config" "$log_file"
python -u src/train.py --config "$config" 2>&1 | tee "$log_file"

실행:

chmod u+x run_train.sh
bash -n run_train.sh
shellcheck run_train.sh  # 설치돼 있다면
./run_train.sh --help
./run_train.sh --config configs/base.yaml --name baseline

핵심:

  • set -euo pipefail: 오류·미정의 변수·파이프 중간 실패를 놓치지 않음
  • 변수 인용: "$config"
  • 입력 검증
  • eval 사용 금지
  • 비밀을 인자로 넘기면 프로세스 목록에 보일 수 있으므로 비밀 관리 체계를 사용

18. 보안 수칙

18.1 SSH

  • host key fingerprint를 검증한다.
  • 개인키에 passphrase를 사용한다.
  • 서버별 키를 분리한다.
  • ForwardAgent yes를 기본값으로 두지 않는다.
  • SSH config와 개인키 권한을 제한한다.
  • 퇴사·프로젝트 종료·노출 시 키를 폐기한다.
  • StrictHostKeyChecking no와 /dev/null known_hosts를 습관적으로 쓰지 않는다.

18.2 Ghostty Secure Keyboard Entry

Ghostty macOS는 암호 프롬프트를 감지하거나 사용자가 수동으로 Secure Keyboard Entry를 켤 수 있고, 활성화 시 우측 상단 잠금 아이콘으로 표시한다.4 이는 다른 프로세스의 키 이벤트 접근을 줄이는 macOS 기능이지만, 피싱 프롬프트·악성 원격 서버·화면 공유·키 자체 유출을 모두 해결하는 만능 장치는 아니다.

18.3 OSC 52와 클립보드

원격 애플리케이션이 OSC 52를 이용해 로컬 클립보드와 상호작용할 수 있다. 편리하지만 신뢰하지 않는 원격 호스트나 프로그램에 클립보드 접근을 허용할 때는 민감 정보가 복사·변경될 가능성을 고려한다. 현재 Ghostty의 클립보드 관련 설정과 승인 정책을 Option Reference에서 확인한다.

18.4 환경 변수와 .env

umask 077
printf 'API_TOKEN=%s\n' '<SECRET>' > .env
chmod 600 .env

하지만 shell history, 로그, notebook output, process arguments에 비밀이 남지 않도록 해야 한다. .env를 .gitignore에 추가하고 조직의 secret manager가 있다면 우선한다.

18.5 공급망

  • pip install 전 패키지 이름과 공식 출처 확인
  • 잠금 파일과 hash 검증 체계 검토
  • 출처 불명의 설치 스크립트를 pipe로 shell에 바로 넘기지 않기
  • 모델 파일과 pickle은 임의 코드 실행 위험을 고려
  • 서버 관리자가 제공한 module/container/image를 우선

19. 장애 해결 플레이북

19.1 접속 시간 초과

ssh -vv gpu-lab
nc -vz <HOST> <PORT>

확인 순서:

  1. 인터넷·VPN
  2. <HOST>, <PORT> 오타
  3. DNS 해석
  4. 방화벽·접근 허용 IP
  5. jump host
  6. 서버 가동 여부

nc 설치 여부와 옵션은 환경에 따라 다르다.

19.2 Permission denied (publickey)

ssh -vv gpu-lab
ssh-add -l
ls -ld ~/.ssh
ls -l ~/.ssh/id_ed25519_gpu_lab*
ssh -G gpu-lab | grep -Ei 'hostname|user|port|identityfile|identitiesonly'

서버 측:

chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys

계정명, 공개키 등록 여부, 사용 중인 개인키, 키 파일 권한을 확인한다.

19.3 host key가 바뀜

경고를 무시하거나 known_hosts 전체를 삭제하지 않는다.

  1. 관리자에게 서버 재설치·키 교체 여부 확인
  2. 새 fingerprint를 신뢰 가능한 채널로 검증
  3. 정확한 항목만 제거
ssh-keygen -F <HOST>
ssh-keygen -R <HOST>  # 검증이 끝난 뒤에만

비표준 포트는 known_hosts 표기가 [host]:port일 수 있다.

19.4 Error opening terminal: xterm-ghostty

printf '%s\n' "$TERM"
infocmp "$TERM"
ghostty +ssh --help
  • 지원 버전이면 ghostty +ssh -- <DEST>
  • shell integration의 ssh-terminfo 확인
  • 서버의 tic, terminfo 설치 가능 여부 확인
  • 불가하면 해당 호스트에만 xterm-256color fallback 검토

19.5 키·Backspace·색상이 이상함

printf 'TERM=%s COLORTERM=%s\n' "$TERM" "${COLORTERM:-}"
infocmp "$TERM" | head

문제가 Ghostty, SSH, tmux, 원격 앱 중 어디서 시작되는지 층별 비교한다.

  1. Mac 로컬 shell
  2. SSH 직후
  3. tmux 밖
  4. tmux 안
  5. 특정 앱 안

19.6 SSH가 자주 끊김

Host gpu-lab
    ServerAliveInterval 60
    ServerAliveCountMax 3

이는 끊김을 감지하고 일부 idle 연결을 유지하는 데 도움을 주지만 네트워크 장애 자체를 없애지는 않는다. 장시간 작업은 tmux·체크포인트를 사용한다.

19.7 Jupyter 페이지가 안 열림

서버:

ss -ltnp 2>/dev/null | grep ':<JUPYTER_PORT>'
curl -I http://127.0.0.1:<JUPYTER_PORT>/

Mac:

lsof -nP -iTCP:<LOCAL_PORT> -sTCP:LISTEN
ssh -vv -N -L <LOCAL_PORT>:127.0.0.1:<JUPYTER_PORT> gpu-lab

서버에서 Jupyter가 살아 있는지, 포트가 맞는지, 로컬 포트가 충돌하는지 확인한다.

19.8 디스크가 꽉 참

df -h
df -i
du -sh "$HOME"/* 2>/dev/null | sort -h

체크포인트·캐시·로그를 무조건 삭제하지 않는다. 보존 정책을 세우고 오래된 파일을 목록화한 뒤 백업·삭제한다.

19.9 Python 패키지가 다른 환경에 설치됨

which python
which pip
python -m pip --version
python -c 'import sys; print(sys.executable); print(sys.path)'

항상 pip 대신 python -m pip를 사용하면 현재 Python과의 연결을 확인하기 쉽다.

19.10 GPU가 안 보임

nvidia-smi
printf '%s\n' "${CUDA_VISIBLE_DEVICES:-not-set}"
python -c 'import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available())'

드라이버, 할당, 컨테이너, 환경, 프레임워크 설치 문제를 분리한다. 로그인 노드에 GPU가 없는 HPC도 흔하므로 스케줄러 할당 여부를 확인한다.

23. 정답과 해설

  1. Ghostty는 입력·출력을 표시하는 터미널 앱, zsh는 명령을 해석하는 shell, SSH는 원격 연결 프로그램/프로토콜, Linux 서버는 실제 계산이 실행되는 원격 운영체제다.
  2. ~는 현재 시스템에서 현재 사용자 $HOME의 축약이므로 시스템·계정마다 다르다.
  3. Cmd+C는 macOS GUI의 복사, Ctrl+C는 터미널 전면 프로세스에 보통 SIGINT를 보낸다.
  4. 중간자 공격 또는 잘못된 서버에 연결하면서도 신뢰 항목을 저장할 수 있다.
  5. .pub 공개키만 전달한다. 개인키는 Mac 밖으로 내보내지 않는다.
  6. SSH config 병합 후 실제 적용될 host, user, port, identity 등의 값을 확인한다.
  7. OpenSSH scp에서 -p는 시간·모드 보존에 쓰이고 포트는 -P로 정의되어 있다.
  8. -n/--dry-run으로 삭제 예정 목록을 검토하고 중요 데이터 백업과 경로 방향을 확인한다.
  9. Ghostty 탭은 Mac 앱에 속하지만 tmux는 서버에 살아 있어 로컬 연결이 끊겨도 유지될 수 있다.
  10. 현재 선택한 python 모듈로 pip를 실행하므로 설치 대상 interpreter를 더 명확히 확인할 수 있다.
  11. 아니다. driver가 지원하는 범위, toolkit, 프레임워크 빌드 runtime은 서로 다른 층이다.
  12. Jupyter를 공용 네트워크 인터페이스에 직접 노출하지 않고 SSH 터널을 통해서만 접근하기 위해서다.
  13. 정리·체크포인트·파일 flush 기회를 주지 않아 데이터 손상이나 상태 불일치를 만들 수 있다. SIGINT/SIGTERM을 먼저 쓴다.
  14. $TERM·infocmp 확인 → Ghostty 버전과 +ssh 지원 확인 → ghostty +ssh 또는 ssh-terminfo 통합 → 원격 tic/설치 권한 확인 → 해당 호스트만 xterm-256color fallback 검토 순이다.
  15. tmux/스케줄러, 로그, 체크포인트, Git commit 기록, 환경 기록, 디스크 확인, 재개 테스트, GPU 할당 준수 등이 있다.
  16. DIR이 비었거나 잘못 설정되면 의도치 않은 위치를 삭제할 수 있다. set -u, 비어 있지 않음·허용된 prefix 검증, realpath 확인, find로 대상 출력, 백업, 대화형 또는 격리 삭제를 사용한다.
  17. wrapper는 대화형 shell의 함수이며 자식 프로세스가 실행 파일 ssh를 직접 찾을 때 shell 함수 테이블을 사용하지 않기 때문이다.
  18. HPC 로그인 노드 자체에는 GPU가 없고 계산 노드 할당 후에만 보일 수 있으며, 컨테이너·환경 변수·드라이버 접근 문제일 수도 있다.

25. 용어집

  • terminal emulator: 문자 기반 프로그램과 상호작용하는 화면·입력 앱. Ghostty가 이에 해당한다.
  • shell: 명령을 해석하고 프로그램을 실행하는 환경. zsh, bash 등이 있다.
  • prompt: shell이 입력을 기다리며 표시하는 문자열.
  • local/remote: 각각 Mac과 SSH로 접속한 서버.
  • SSH client/sshd: 접속을 시작하는 프로그램과 서버에서 요청을 받는 daemon.
  • host key: 서버 신원을 증명하는 키.
  • user key: 사용자를 인증하는 공개키/개인키 쌍.
  • fingerprint: 키를 비교하기 쉬운 짧은 표현.
  • agent: 복호화된 개인키 사용을 중개하는 프로세스.
  • agent forwarding: 원격에서 로컬 agent를 사용할 수 있게 하는 기능. 신뢰 경계가 넓어진다.
  • port forwarding: SSH 연결을 통해 TCP 연결을 전달하는 기능.
  • terminfo: 터미널 기능 정보를 응용 프로그램에 제공하는 데이터베이스.
  • TERM: 현재 터미널 유형을 나타내는 환경 변수.
  • shell integration: 터미널과 shell이 프롬프트·작업 디렉터리·SSH 등을 더 잘 연동하는 코드.
  • OSC 52: 터미널 제어 시퀀스를 이용한 클립보드 상호작용 방식.
  • tmux: 서버에서 세션·window·pane을 유지하는 터미널 멀티플렉서.
  • process/PID: 실행 중 프로그램과 그 식별 번호.
  • signal: 프로세스에 중단·종료 등을 요청하는 메커니즘.
  • stdout/stderr: 일반 출력과 오류 출력 스트림.
  • pipe: 한 프로그램의 출력을 다른 프로그램의 입력으로 연결.
  • venv/Conda environment: 프로젝트별 Python·패키지 격리 환경.
  • CUDA driver/runtime/toolkit: NVIDIA GPU 접근을 구성하는 서로 다른 소프트웨어 층.
  • checkpoint: 학습을 재개하거나 모델을 보존하기 위한 상태 파일.
  • OOM: 메모리 부족(Out Of Memory).
  • quota: 사용자·그룹이 사용할 수 있는 저장 공간 제한.
  • inode: 파일 메타데이터 객체. 작은 파일이 너무 많으면 용량이 남아도 고갈될 수 있다.
  • dry-run: 실제 변경 없이 예정 동작을 보여주는 실행.
  • bastion/jump host: 내부 서버로 들어갈 때 거치는 중계 서버.
